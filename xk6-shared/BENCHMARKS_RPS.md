# xk6-shared — RPS по всем методам (замер)

Пропускная способность (throughput) каждого публичного метода, из **самого k6**
(через goja-границу, 1000 VU), а не Go-микробенч. Это то, что реально важно для
нагрузки.

## Как читать таблицу

- **Числа = тысяч операций в секунду** на ОДИН генератор. Пример: `2894` = 2 894 000 ops/s (2.9 млн/с).
- **Столбцы `1k / 20k / 200k` = РАЗМЕР ПУЛА в ЭЛЕМЕНТАХ** (не символы, не КБ):
  - `1k`  = 1 000 элементов в списке/таблице/пуле
  - `20k` = 20 000 элементов
  - `200k` = 200 000 элементов
- Для справки в памяти (пул строк `eventId:integration`, ~12 Б/элемент):
  `1k` ≈ 12 КБ, `20k` ≈ 240 КБ, `200k` ≈ 2.3 МБ. Пул объектов (~150 Б/эл): `200k` ≈ 30 МБ.
- Замер: k6, 1000 VU, 5 с/метод, чистый counter-rate (без Date.now — он сам жрёт CPU и врёт на лёгких операциях).

## Как зависит от размера пула

- **O(1)-методы** (random/at/get/tableField/счётчики/getPath): RPS почти НЕ зависит
  от размера. Просадка 1k→200k (~20%) — это общий RAM процесса, не стоимость операции.
- **O(N)-методы** (`snapshot`, `snapshotShard`): копируют ВЕСЬ пул → RPS падает с
  размером. **Только setup/teardown/debug, НЕ hot-loop.** Нужен один элемент — `random`/`at`.
- `randomN` — теперь O(n) (rejection-sampling): ~1.2–1.5M на любом размере (раньше
  обходил весь пул: на 200k давал всего 7k — было ×170 медленнее).

## Выводы

1. **Почти всё O(1)** — держит 1.3–2.9 млн ops/s даже на пуле в 200k элементов.
2. **Только 2 метода O(N)** (`snapshot`, `snapshotShard`) обваливаются с размером —
   это setup/debug (копируют весь пул). В hot-loop бери элемент по одному.
3. **Самое «медленное» из рабочего** — `update` в один ключ (0.5M, CAS-ретраи;
   под массовой записью → `updateShard`) и загрузчики (парсинг файла, только setup).
4. **Наш боевой кейс** (пул строк `eventId:integration`, `random`): 1.8M ops/s на
   200k событий — с большим запасом.

Сравнение: redis localhost ~77µs/оп (~13k RPS одним потоком) → shared ~×80 по RPS.
vs kv (memory): shared в 2.2–4.3× быстрее И корректнее (kv теряет incr/update).

Бенч-скрипт: `kv-bench/tps-all.js` (`-e M=<Метод> -e POOL=<размер> -e VUS=1000`).
